# AI 陪伴 Agent · AI Native User Journey 重画设计规格

日期：2026-07-27
状态：用户已确认方向，待书面规格复核

## 1. 目标

重画现有 `ai-companion-dual-audience-user-story-flow.html`，把产品从一次性的 onboarding 流程升级为持续运转的 AI Native 关系循环。

新版图必须表达：

1. 产品是纯软件 AI 陪伴 Agent，不包含实体机器人或硬件控制。
2. 首次关系设置只是前置流程，日常陪伴才是核心循环。
3. 用户每次聊天、语音、剧情选择和小游戏行为都会进入 Agent 决策。
4. Agent 不只生成回复，还会提出动作、剧情、关系状态、记忆和主动陪伴计划。
5. 关系状态和长期记忆必须经过确定性的审核与用户授权，不能由 LLM 直接写入。
6. 当前体验会影响下一次体验，形成可持续但不鼓励依赖的关系闭环。
7. 成人与青少年体验、模型策略、数据和付费激励保持隔离。

## 3. 信息架构

### 3.1 Shared Entry / 共用入口

共享入口只负责：

- 自主注册
- AI 身份披露
- 年龄与地区判断
- 13 岁以下停止
- 18+ 进入成人 Flow
- 13-17 岁进入青少年 Flow

共用入口不承载关系、记忆或剧情逻辑。

### 3.2 Flow A · Adult Companion / 成人陪伴

#### 一次性 onboarding

用户层：

1. 确认成人身份与数据同意。
2. 选择朋友、家人、恋人或生活伙伴关系。
3. 设置语气、记忆、主动频率和静默时间等边界。
4. 通过结构化剧情和选择完成初次相识。
5. 查看、修改或拒绝系统形成的人格假设。

Agent 与大模型系统层：

1. Consent & Policy Gate：确认年龄、地区、AI 披露与数据权限。
2. Relationship Contract：创建角色、边界和初始关系阶段。
3. Discovery Story Planner：生成安全的剧情分支。
4. Profile Hypothesis：形成带置信度、可被用户纠正的人格与偏好假设。

#### 持续关系循环

用户层：

1. 通过聊天、语音、剧情选择或小游戏发起互动。
2. 收到回复、动作、新剧情和可解释的关系变化。
3. 选择继续、喜欢、忽略、拒绝、调整边界或删除记忆。
4. 在同意范围内收到后续主动联系。

Agent 与大模型系统层：

1. Input Understanding：识别输入模态、意图、情绪和当前任务。
2. Safety Pre-check：在组装和生成前识别高风险输入。
3. Context Assembler：组装角色契约、关系状态、用户确认的记忆、剧情进度和短期上下文。
4. Decision Harness：输出结构化的回复、动作、剧情、状态变化提案、记忆候选和后续计划。
5. State Transition Guard：验证关系变化是否符合边界、年龄、频率和反操控规则。
6. State & Memory Commit：只写入通过审核的关系状态、剧情进度和经用户授权的长期记忆。
7. Experience Router：把决策映射为文本、语音、动作、剧情或小游戏反馈。
8. Proactive Scheduler：根据承诺、重要事件、用户反馈和静默时间安排下一次联系。

主动联系被忽略或拒绝时，只降低频率或关闭对应触达，不降低关系等级、不制造内疚。

### 3.3 Flow B · Teen Story / 青少年结构化剧情

#### 一次性 onboarding

用户层：

1. 13-17 岁自主注册并看到 AI 身份说明。
2. 选择朋友、队友、导师或虚构角色。
3. 设置主题、内容强度、提醒频率和随时停止控制。
4. 进入审核过的结构化剧情。

系统层：

1. Teen Policy Gate：应用地区化未成年人策略。
2. Approved Story Graph：只使用审核后的角色、主题和安全节点。
3. Minimal Preference Profile：只保存兴趣、内容舒适度和故事进度。

#### 持续故事循环

用户层：

1. 通过有限剧情选项和小游戏做选择。
2. 收到新剧情、角色动作和故事进度反馈。
3. 可以继续、重玩、换故事、停止或删除偏好。
4. 只接收明确 opt-in 的安全提醒，不使用恋爱式主动联系。

系统层：

1. 对选择进行持续风险分类。
2. 在审核剧情图谱中选择或受限生成下一节点。
3. 更新故事进度、兴趣和内容舒适度。
4. 禁止固定人格标签、恋爱关系状态、性内容和开放式关系记忆。
5. 命中自伤、虐待、诱导或依赖风险时立即暂停故事，切换到确定性安全模板和地区资源。

## 4. 安全与状态边界

安全编排独立于陪伴人格，并同时作用于输入前和输出后。

LLM 只能输出状态变化提案，状态引擎负责最终决定：

```json
{
  "reply": "用户可见的回复",
  "experience_action": "界面或剧情动作",
  "state_delta_proposal": {},
  "memory_candidate": {},
  "proactive_follow_up": {}
}
```

状态审核至少验证：

- 年龄与地区策略
- 用户设置的关系边界
- 记忆授权
- 主动触达频率与静默时间
- 未成年人限制
- 情感操控与依赖风险
- 危机与真人支持升级条件

## 5. 图形拓扑

每条 Flow 使用两个泳道：

- `User Layer / 用户层`
- `Agent & LLM System Layer / Agent 与大模型系统层`

布局遵循以下规则：

1. onboarding 作为左到右的单向前置链路。
2. 核心关系循环单独成组，与 onboarding 视觉分区。
3. 用户输入与对应系统处理使用同列垂直连接。
4. 系统内部决策与状态更新只使用水平连接。
5. 系统输出通过单一垂直线返回用户体验节点。
6. 主动陪伴通过最右侧专用回路进入下一轮，不穿过任何节点。
7. 安全风险使用最右侧独立红色出口，不与正常回路共线。
8. 每条异常线只指向一个明确节点，不出现多条线重合后再分叉。

## 6. 视觉变化

- 主标题改为“AI Native 持续关系循环”。
- “LLM Layer”统一改为“Agent & LLM System Layer”。
- 新增视觉分组：
  - `One-time Onboarding / 一次性设置`
  - `Persistent Relationship Loop / 持续关系循环`
- 正常主链路使用蓝色与青色。
- 状态、记忆和策略使用紫色。
- 用户可控的完成状态使用绿色。
- 风险、暂停和降级使用红色虚线。
- 主动回路仅使用一条绿色外侧连接线。

## 7. 验收标准

1. 打开 HTML 无 JavaScript 或页面加载错误。
2. 成人与青少年两条 Flow 都包含 onboarding 和持续循环。
3. 图中明确出现 Input Understanding、Context Assembler、Decision Harness、State Transition Guard、Memory Commit 和 Proactive Scheduler。
4. 每次体验能从用户输入流向系统决策，再返回用户输出并进入下一轮。
5. LLM 不直接修改关系或记忆。
6. 青少年无恋人模式、开放聊天和开放式关系记忆。
7. 安全出口与正常路径分离。
8. 所有连接线为水平或垂直，不穿过卡片，不出现难以判断归属的重合线。
9. HTML 在桌面宽度下完整可读，移动端可横向滚动。
10. 本次不生成或提交 PNG。
